# Мольфар — моніторинг мережі на Orange Pi Zero 3

*English version: [README.en.md](README.en.md)*

Легкий сервіс (Python + SQLite, ~40 МБ RAM), який:

- **Speedtest** — щодня у вибраний час запускає серію (за замовчуванням 5 тестів з інтервалом 5 хв) і зберігає середнє; кнопки «Один тест», «Серія», «Зупинити».
- **Вибір сервера speedtest** — автовибір найближчого або конкретний сервер зі списку / пошуку. Якщо вибраний сервер недоступний, тест можна автоматично повторити на автовибраному (у результаті буде позначка «[замість …]»).
- **Пінг** — постійно (за замовчуванням раз на 60 с по 20 пакетів) пінгує `1.1.1.1`, `8.8.8.8` і третю адресу на ваш вибір; рахує втрати, RTT (мін/сер/макс) і **джитер**. Плюс до 37 **додаткових хостів** (разом — 40); будь-який можна вивести плиткою на «Огляд» галкою «На Огляді».
- **Історія** — графіки й підсумки за добу / тиждень / місяць / рік, експорт у CSV. Додаткові хости — у таблиці підсумку, на графік додаються галочкою.
- **«Огляд» з плиток** — кнопка «Змінити розташування»: плитки перетягуються за ⠿ (мишею чи пальцем) або пересуваються стрілками. Порядок зберігається на пристрої й однаковий у всіх браузерах.
- **Telegram** — сповіщення при високих втратах (N перевірок поспіль вище порогу), повідомлення про відновлення з тривалістю збою, опційно — підсумок кожної серії та алерт про низьку швидкість. Якщо інтернету немає, повідомлення чекають у черзі й надходять, щойно зв'язок повернеться.
- **Інциденти** — на «Огляді» статичний індикатор: зелене коло з логотипом мольфара, якщо за останню добу інцидентів не було, і червоне коло зі знаком «!», якщо були або триває зараз (плановий перезапуск сервісу не рахується). Без анімації: хост віддалений, тож червоне коло лишається, щоб ви побачили його вже після відновлення мережі; натискання відкриває вкладку «Інциденти». У вкладці: скільки разів і як довго не було інтернету, перезавантаження Pi, скільки Мольфар був недоступний, масовий відвал Wi-Fi-клієнтів, збої роутера. Таймлайн за 24 год, список подій, історія за тиждень/місяць/рік, CSV, сповіщення в Telegram.
- **Провайдер** — визначає поточного інтернет-провайдера (назва, номер AS, зовнішній IP, місто) раз на 10 хв і після кожного speedtest. Історія змін провайдера та IP, провайдер у таблиці серій, сповіщення в Telegram при зміні (зручно, якщо є резервний канал).
- **WireGuard** — вкладка для керування профілями: додати (вставити / завантажити `.conf` або через майстер з генерацією ключів), редагувати, увімкнути/вимкнути тунель, автозапуск, видалити. Стан (handshake, трафік) — і на «Огляді».
- **Мапа мережі** — вкладка з деревом пристроїв локальної мережі «Інтернет → роутер → комутатори / точки доступу → пристрої». Кожен пристрій клікабельний (IP, MAC, виробник, імʼя, підключення, власні події). Мапу можна редагувати: перетягувати пристрої, змінювати, куди вони підключені, тип і сегмент мережі, видаляти й додавати вручну. Зникнення пристрою пишеться в журнал мапи (зберігається 400 днів), після 7 днів офлайн пристрій прибирається з мапи (роутер і сам Мольфар — ніколи). На «Огляді» — картка «Локальна мережа», у Telegram — опційне сповіщення про новий пристрій.
- **Wi-Fi ефір** — сканує сусідні Wi-Fi мережі, малює спектр і водоспад (де ефір чистий / зашумлений) і радить оптимальний канал для роутера в 2.4 і 5 ГГц. Картка на «Огляді» показує найчистіші канали.
- **Діагностика** — окрема вкладка з мережевими інструментами просто з браузера: **ping**, **traceroute** (UDP / ICMP / TCP), **nslookup** (A, MX, TXT…, будь-який DNS-сервер), **telnet** (чи відкритий TCP-порт і що він відповідає) та **iperf3** — пропускна здатність до іншого пристрою; Мольфар може й сам увімкнути iperf3-сервер. Вивід наживо, підсумок у зрозумілому вигляді, історія запусків.
- **Дві мови** — українська та англійська (перемикач UK/EN у шапці або «Налаштування → Загальне»). Мова діє на веб-інтерфейс, Telegram-сповіщення та журнал.
- Веб-інтерфейс з паролем (змінюється прямо в налаштуваннях), адаптований під телефон, світла й темна теми.

## Встановлення

> **Docker** (віртуальна машина / сервер x86_64 або ARM64): `cp .env.example .env && docker compose up -d --build` — див. [DOCKER.md](DOCKER.md).

На Orange Pi (Armbian / Debian / Ubuntu):

```bash
# скопіюйте папку molfar на пристрій, напр.: scp -r molfar user@<ip>:~
cd ~/molfar
sudo ./install.sh
```

Скрипт сам готує систему:

1. **Годинник** — ставить часовий пояс `Europe/Kyiv`, вмикає NTP; якщо NTP не відповідає, бере час з HTTP-заголовка (у Zero 3 немає батарейки RTC, а з неправильним часом apt не працює).
2. **Обов'язкові пакети** — `python3`, `python3-venv`, `python3-pip`, `iputils-ping`, `iproute2`, `wireguard-tools`, `nftables` (потрібен wg-quick для профілів з `AllowedIPs = 0.0.0.0/0`), `sudo`, `curl`, `ca-certificates`, `unzip`, `arp-scan` (мапа мережі), а також NTP-клієнт `systemd-timesyncd` (якщо немає chrony/ntp).
3. **Інструменти діагностики** — `traceroute`, `nslookup`/`dig` (`dnsutils`), `telnet`, `iperf3` для вкладки «Діагностика» — ставляться завжди. **Мережеві утиліти** — `mtr`, `netstat`/`ifconfig`, `ethtool`, `tcpdump`, `iftop`, `nload`, `sqlite3`, `fake-hwclock`, `avahi-utils` (імена пристроїв на мапі) — «за можливості»: якщо якогось пакета немає, встановлення не зупиняється.
4. **WireGuard** — перевіряє модуль ядра; для `DNS =` у профілях налаштовує `resolvconf` (через `systemd-resolved`, якщо він працює, інакше ставить `openresolv`).
5. **Пересилання IPv4** — `net.ipv4.ip_forward=1` постійно: `/etc/sysctl.d/99-zz-molfar-forward.conf` (при кожному завантаженні) і drop-in `molfar.service.d/ip-forward.conf` (при кожному запуску Мольфара). Потрібне для доступу з VPN до інших хостів локальної мережі через Мольфар (плюс зворотний маршрут на роутері LAN: `<мережа VPN> → IP Мольфара`; власну LAN Мольфара не додавайте в його `AllowedIPs`).
6. Ookla Speedtest CLI, користувач `molfar`, сервіс systemd, sudo-правила — і в кінці таблиця перевірки ✓/✗.

Змінні: `TIMEZONE=Europe/Warsaw` (або `keep`), `PORT=8081`, `EXTRA_TOOLS=0` (без утиліт), `WIFI_SCAN=auto|1|0` (Wi-Fi ефір: лише якщо є адаптер / завжди / не ставити), `IP_FORWARD=0` (не вмикати пересилання IPv4), `MOLFAR_PASSWORD=…`, напр. `sudo TIMEZONE=keep EXTRA_TOOLS=0 ./install.sh`.

**Вхід у веб-інтерфейс за замовчуванням: `admin` / `Molfar`.** Поки діє пароль за замовчуванням, інтерфейс показує попередження. Змініть його в **Налаштування → Пароль веб-інтерфейсу** або задайте одразу при встановленні: `sudo MOLFAR_PASSWORD=МійПароль ./install.sh`. Повторний запуск `install.sh` оновлює код, дані зберігаються.

**Забули пароль?** `sudo molfar-reset-password` — повертає пароль з `/etc/molfar.env` (за замовчуванням `Molfar`).

| Що | Де |
|---|---|
| Код | `/opt/molfar` |
| База даних | `/var/lib/molfar/molfar.db` |
| Логін, пароль за замовчуванням, порт | `/etc/molfar.env` (після змін: `sudo systemctl restart molfar`) |
| Пароль, змінений у веб-інтерфейсі | у базі як хеш PBKDF2 (не відкритим текстом) |
| Логи | `journalctl -u molfar -f` |

## Віддалений доступ через WireGuard

Сервіс слухає `0.0.0.0:8080`, тож доступний з будь-якої мережі, яку маршрутизує ваш WireGuard (10.10.105.x, 10.10.106.x …).

- **WireGuard на роутері, Pi у його LAN** — нічого додатково не треба: підключіться до тунелю і відкрийте `http://<LAN-IP Pi>:8080`. Бажано закріпити за Pi статичний IP (DHCP-резервація на роутері).
- **Pi сам є WireGuard-піром** — див. `deploy/wg0.conf.example` (з `PersistentKeepalive = 25`, щоб Pi був доступний з-за NAT).

### Профілі WireGuard у веб-інтерфейсі

Вкладка **WireGuard** керує тунелями, через які Мольфар сам підключається до ваших мереж (`/etc/wireguard/<назва>.conf` + `wg-quick@<назва>`):

- **Додати** — вставте `.conf` від роутера, завантажте файл або заповніть **майстер** (кнопка «Згенерувати» створює ключі; публічний ключ передайте адміністратору сервера).
- **Редагувати** — приватний ключ показується як `<hidden>` і зберігається без змін, якщо його не замінити. Перед записом робиться копія `<назва>.conf.bak`. Активний тунель перезапускається.
- **Увімкнути / Вимкнути / Автозапуск / Видалити** — кнопки на картці профілю.
- **Захист від втрати доступу.** Після увімкнення або зміни активного тунелю браузер за кілька секунд підтверджує, що Мольфар досі доступний. Якщо підтвердження не надійде за 60 с (наприклад, `AllowedIPs = 0.0.0.0/0` «забрав» увесь трафік), тунель автоматично вимкнеться.
- **Безпека.** Веб-сервіс не має root: усі зміни виконує помічник `/usr/local/sbin/molfar-wg`, дозволений через sudo лише йому. Помічник сам перевіряє кожен параметр і **забороняє `PreUp/PostUp/PreDown/PostDown/SaveConfig`** — вони виконують довільні команди від root. Профілі з такими рядками, створені вручну, показуються «лише для перегляду»; редагуйте їх через SSH.

Перевірка на пристрої після оновлення:
```bash
sudo -u molfar sudo -n /usr/local/sbin/molfar-wg list    # {"ok": true, "profiles": [...]}
sudo wg show                                              # після «Увімкнути» у вебі
systemctl status wg-quick@<назва> --no-pager
```

Третьою адресою пінгу зручно ставити шлюз іншого сайту (напр. `10.10.106.1`) — тоді видно і якість самого тунелю.

## Додаткові хости для пінгу

Три основні адреси (**Налаштування → Пінг**) показуються плитками на «Огляді». Якщо потрібно стежити ще за чимось — NAS, камерою, точкою доступу, сервером в іншій мережі через WireGuard, — додайте їх у **Налаштування → Додаткові хости для пінгу** (до 37, разом з основними — 40).

- **Галка «На Огляді»** (поруч з «Алерти») — хост отримує власну плитку на «Огляді», яку можна переставляти, як і решту. Такий хост пінгується **так само часто, як основні** (інтервал і кількість пакетів з **Налаштування → Пінг**), і в «Історії» завжди є на графіку.
- Хости **без цієї галки** на «Огляді» не показуються: останній результат (втрати, RTT, джитер, час) видно в самому списку, історію — в **«Історії»** (у таблиці підсумку, на графік — галочкою «На графіку»). Вони пінгуються **окремим розкладом**: за замовчуванням раз на 300 с по 10 пакетів (**Налаштування → Пінг → Додаткові хости**), не більше 10 одночасно. Так 40 хостів не роздувають базу: за 400 днів це ~4 млн рядків замість ~23 млн при щохвилинному пінгу.
- **Алерти в Telegram** — за тими ж правилами, що й для основних (поріг втрат, N перевірок поспіль), окремо вмикаються для кожного хоста. Зверніть увагу: «N перевірок поспіль» для додаткових хостів — це N × їхній інтервал. У повідомленні хост показується з назвою: «NAS (192.168.50.20)».
- «Моніторинг пінгу» та «Пауза пінгу під час speedtest» діють і на додаткові хости. Кнопка «Пінг зараз» на «Огляді» пінгує основні адреси і хости «На Огляді».
- Після видалення хоста його історія лишається (до кінця терміну зберігання).

## Мапа мережі

Вкладка **Мапа мережі** показує пристрої вашої локальної мережі деревом: зліва провайдер (з визначення провайдера), далі роутер, комутатори й точки доступу, праворуч пристрої. Кабель — суцільна лінія, Wi-Fi — пунктир, колір підпису — сегмент мережі (LAN, сервери, IoT, гості).

- **Пошук пристроїв** — `arp-scan` по підмережі інтерфейсу з маршрутом за замовчуванням раз на 5 хв (WireGuard-інтерфейси пропускаються). Знаходить і тих, хто не відповідає на пінг. Сервіс не має root: systemd дає йому лише `CAP_NET_RAW`. Якщо `arp-scan` не спрацює, використовується пінг + таблиця ARP (видно в «Стан сканування»).
- **Імена** — з DNS роутера (у ASUS і TP-Link це імена з DHCP), далі з mDNS. **Виробник** — за MAC з бази IEEE. Телефони з випадковою MAC позначаються «приватна MAC».
- **Тип і кабель/Wi-Fi** — здогадка за виробником та іменем. Будь-яку здогадку можна виправити в картці пристрою; ручні значення сканер більше не перезаписує.
- **Офлайн** — пристрій не відповідав довше за «Офлайн після» (15 хв, тобто три сканування — щоб телефони, що дрімають, не «зникали»). Подія йде в журнал мапи.
- **7 днів офлайн → прибирається з мапи.** Лишається в журналі й у списку «Прибрані з мапи», звідки його можна повернути. Щойно знову зʼявиться в мережі — повертається сам. Роутер і Мольфар не прибираються ніколи; для інших пристроїв є «Завжди показувати на мапі».
- **Журнал мапи** — нові пристрої, офлайн/онлайн, зміна IP, усі ручні зміни. Зберігається 400 днів (налаштовується). Нові пристрої також пишуться в загальний журнал Мольфара.
- **Редагування** — кнопка «Редагувати»: перетягуйте пристрої; відпустіть на роутері, комутаторі чи точці доступу — зміниться підключення (є «Скасувати»). У картці пристрою: назва, тип, IP/MAC, сегмент, «Підключено до», кабель чи Wi-Fi, SSID, діапазон, примітка. «Додати» — ручні вузли, наприклад некерований комутатор без IP. «Видалити з мапи» — з опцією «Більше не показувати».
- **Комутатори й точки доступу** сканер окремими вузлами не бачить (некерований комутатор не має IP, точка доступу виглядає як звичайний пристрій). Додайте їх або змініть тип знайденого пристрою на «Точка доступу», а потім перетягніть на них клієнтів.

Налаштування — **Налаштування → Мапа мережі** (інтервал, «офлайн після», «прибирати після», термін журналу, інтерфейс) і **Telegram → Сповіщати про новий пристрій у мережі**. Перше сканування після встановлення сповіщень не надсилає — інакше «новими» були б усі пристрої.

## Wi-Fi ефір

Вкладка **Wi-Fi ефір** допомагає вибрати канал для роутера: вона сканує сусідні мережі вбудованим Wi-Fi Orange Pi (`wlan0`) і показує, де ефір чистий, а де зашумлений.

**Це необовʼязкова функція.** На системі без Wi-Fi адаптера встановлення проходить як завжди: `iw` і помічник не ставляться, вкладки й плитки на «Огляді» немає, у підсумку `install.sh` — сірий рядок «не встановлено», а не помилка. Керування: змінна `WIFI_SCAN` під час встановлення (`auto` — за замовчуванням, лише якщо є адаптер; `1` — ставити завжди, напр. під USB-адаптер, який підключите пізніше; `0` — не ставити й прибрати помічник) і перемикач **Налаштування → Wi-Fi ефір → Увімкнути Wi-Fi ефір**. Якщо `iw` не вдалося встановити, решта Мольфара працює.

- **Рекомендація** — для 2.4 ГГц найкращий із каналів без перекриття 1/6/11 (і підказка, якщо 12–13 значно чистіші: деякі пристрої з США їх не бачать). Для 5 ГГц — найкращий блок 80 МГц і основний канал у ньому; DFS-канали (52–144) позначені, і якщо найкращий блок DFS, показано й найкращий без DFS. Позначте свою мережу кнопкою «це моя» в таблиці (або в налаштуваннях): вона не рахується завадою, і Мольфар скаже, чи варто переходити з поточного каналу та на скільки покращиться оцінка.
- **DFS / без DFS** — для 5 ГГц під смугою каналів підписано групи: **без DFS** — 36–48 і 149–165 (роутер вмикає їх одразу), **DFS** — 52–144 (перед стартом роутер ~1 хв слухає ефір на радари, на 120–128 у ЄС до 10 хв, і може сам змінити канал, почувши радар). DFS-зона заштрихована на спектрі й підписана на водоспаді; у рекомендації, рейтингу блоків і таблиці мереж стоїть значок «DFS» або «без DFS». Які канали DFS, визначається за прапорцями самого адаптера (`radar detection` в `iw phy`), а якщо їх немає — за стандартом.
- **Спектр** — кожна мережа як «горб» шириною свого каналу (20/40/80/160 МГц) і висотою сигналу; ваша мережа — синя, рекомендований канал — зелена рамка. Під спектром — смуга оцінок кожного каналу 0–100 (зелений — чисто, жовтий — помірно, червоний — зашумлено). Наведіть на горб чи клітинку — деталі.
- **Водоспад** — оцінка кожного каналу в часі (доба / тиждень / місяць): що темніше-червоніше, то шумніше. Увімкніть «Сканувати ефір за розкладом» — увечері ефір зовсім інший, ніж удень, і рекомендація «за добу» надійніша за один знімок.
- **Як рахується оцінка.** Звичайний Wi-Fi-чип не віддає сирий спектр, тому спектр моделюється з того, що чує адаптер: потужність кожної сусідньої мережі в смузі каналу плюс бічні пелюстки за маскою 802.11. Часткове перекриття (напр. канали 3 і 6) вважається гіршим за спільний канал, бо мережі на одному каналі ділять ефір чемно (CSMA), а при частковому — заважають одна одній. Якщо драйвер повідомляє **зайнятість ефіру** (`iw survey`, busy time), вона додається до оцінки — це бачить і не-Wi-Fi завади (мікрохвильовки, камери, Bluetooth). Чи доступна вона, видно у картці рекомендації.
- **Безпека.** Сканування потребує прав адміністратора мережі, тому його виконує помічник `/usr/local/sbin/molfar-wifi` через sudo. Він лише сканує (`iw scan`, `iw survey dump`): не підключається до мереж і нічого не змінює. Якщо `wlan0` вимкнений, помічник вмикає його на час сканування і вимикає назад.
- **Якщо Мольфар сам підключений через Wi-Fi**, під час сканування (3–5 с) звʼязок ненадовго переривається, і пінг може показати сплеск. За розкладом сканування не запускається під час speedtest.

Перевірка вручну:

```bash
sudo -u molfar sudo -n /usr/local/sbin/molfar-wifi scan wlan0 | head -c 300   # {"ok": true, "scan": "BSS ...
rfkill list                                                                     # якщо «Soft blocked: yes» — sudo rfkill unblock wifi
```

Налаштування — **Налаштування → Wi-Fi ефір** (розклад, інтервал, мої мережі, інтерфейс, скільки днів зберігати історію; за замовчуванням 30).

## Діагностика

Вкладка **«Діагностика»** — мережеві інструменти, які запускаються на самому Мольфарі (тобто з тієї мережі, де він стоїть), без SSH:

| Інструмент | Для чого | Параметри |
|---|---|---|
| **Ping** | втрати, затримка, джитер до будь-якої адреси — разово, без запису в історію моніторингу | пакетів (1–100), розмір, IPv4/IPv6 |
| **Traceroute** | через які вузли йдуть пакети і де з'являються затримка чи втрати | режим **UDP** / **ICMP** / **TCP** (порт), макс. вузлів, імена вузлів |
| **NSLookup** | що відповідає DNS; порівняння DNS роутера і, напр., `1.1.1.1` | тип запису A, AAAA, MX, TXT, NS, CNAME, SOA, PTR, SRV, CAA; DNS-сервер |
| **Telnet** | чи відкритий TCP-порт (SSH, пошта, вебсервер, камера) і що сервер пише першим | порт (швидкі кнопки 22, 25, 80, 443…), скільки чекати |
| **iperf3** | реальна пропускна здатність між Мольфаром і iperf3-сервером (ПК, NAS, роутер, VPS, другий кінець VPN) | порт, тривалість, потоки (1–16), напрямок ↑ / ↓ / ⇅, TCP або UDP зі швидкістю |

- **Вивід наживо** — довгий traceroute видно рядок за рядком; кнопка «Зупинити» перериває перевірку. Над виводом — підсумок: плитки втрат / затримки / джитера, таблиця вузлів трасування зі смугами затримки, стан порту («відкритий» / «відмовлено» / «немає відповіді — фільтрується»), для iperf3 — швидкість, повтори (TCP) або втрати й джитер (UDP), навантаження CPU і графік по секундах.
- **iperf3-сервер на Мольфарі** — перемикач у тій самій вкладці: Мольфар слухає порт (за замовчуванням `5201`), і тест можна запустити з ноутбука чи телефона (`iperf3 -c <IP Мольфара>`; `-R` — у зворотний бік). Так видно швидкість Wi-Fi або VPN саме до Мольфара. Можна задати автовимкнення (15 хв / 1 год / 4 год / 24 год); стан зберігається після перезапуску. Список останніх клієнтів і журнал сервера — там само. Сервер запускає сам Мольфар (системна служба `iperf3` вимкнена).
- **Історія** — останні 200 запусків з підсумком; клік по рядку відкриває збережений вивід.
- **Безпека** — адреса приймається лише як IP або ім'я вузла, усі параметри мають межі, команди запускаються без shell. Одночасно — до 3 перевірок, iperf3 — по одній.
- На Orange Pi Zero 3 процесор може стати межею для iperf3 на гігабіті — якщо CPU під час тесту близько 100%, вкладка про це попередить; спробуйте 2–4 потоки.

Утиліти `traceroute`, `nslookup` (`dnsutils`), `telnet` та `iperf3` `install.sh` ставить завжди. API: `GET /api/diag`, `POST /api/diag/run` (`{"tool":"traceroute","host":"1.1.1.1","mode":"icmp"}`), `GET /api/diag/jobs/{id}?since=N`, `POST /api/diag/jobs/{id}/stop`, `POST /api/diag/iperf/server` (`{"enabled":true,"port":5201,"auto_off_min":60}`).

## Інциденти

| Тип | Як визначається |
|---|---|
| **Немає інтернету** | Усі публічні адреси пінгу (1.1.1.1, 8.8.8.8; приватні на зразок 10.10.105.1 не враховуються) не відповіли `inc_inet_confirm` перевірок поспіль (за замовч. 2, тобто ~2 хв). Тоді Мольфар пінгує шлюз за замовчуванням: роутер відповідає → проблема провайдера; мовчить → локальна мережа чи роутер; маршруту немає → кабель / Wi-Fi самого Pi. Збій самої програми `ping` обривом не вважається. |
| **Перезавантаження Pi і простій Мольфара** | Кожні 30 с сервіс записує heartbeat і `boot_id` ядра, при штатній зупинці — `clean_stop`. Після старту: інший `boot_id` + `clean_stop` → перезавантаження системи; інший `boot_id` без `clean_stop` → зникло живлення або плата зависла; той самий `boot_id` → перезапуск сервісу (оновлення) або збій. Простій = від останнього heartbeat до старту сервісу (точність ±30 с). |
| **Відвал Wi-Fi** | Мольфар опитує роутер (раз на `router_poll_min` хв) і порівнює список Wi-Fi-клієнтів з попереднім. Інцидент — лише коли між двома опитуваннями зникли **всі** Wi-Fi-клієнти одночасно, а до цього їх було щонайменше `wifi_drop_min` (2). Часткові відключення (хтось пішов з дому з телефоном) не рахуються. Якщо роутер не віддав жодного клієнта взагалі (навіть кабельних і самого Pi), це вважається збоєм опитування. Інцидент закінчується, щойно підключився хоч один Wi-Fi-клієнт. |
| **Роутер недоступний** | Два опитування поспіль без відповіді → «роутер недоступний». Коли відповів: ASUS повідомляє час завантаження → видно, чи він перезавантажувався; TP-Link — лише аптайм WAN (перепідключення WAN або перезавантаження). Перезавантаження між опитуваннями теж фіксується. |

**Годинник.** В Orange Pi Zero 3 немає батарейки годинника, тому після ввімкнення час неправильний, доки не спрацює NTP. Простій після перезавантаження Мольфар записує лише після синхронізації часу, а початок обриву, що стався до неї, перераховує за монотонним годинником. Якщо інтернету немає і NTP так і не синхронізувався, тривалість позначається як невідома.

**Роутер** (**Налаштування → Інциденти та роутер**):
- **TP-Link** (Archer C64, C6, AX…) — бібліотека `tplinkrouterc6u`. Потрібен локальний пароль адміністратора; якщо вхід не проходить, бібліотека може вимагати «web encrypted password» (див. її README). TP-Link дозволяє лише одного адміністратора, тож під час опитування вас може викинути з веб-інтерфейсу роутера; Мольфар щоразу виходить одразу.
- **ASUS** (ExpertWiFi EBR63, RT-…) — бібліотека `asusrouter`, сесія тримається між опитуваннями.
- Кнопка «Перевірити з'єднання» показує кількість клієнтів без збереження налаштувань.

**Звіт** (вкладка «Інциденти», доба / тиждень / місяць / рік): скільки часу і скільки разів не було інтернету (найдовше, в середньому, з чиєї вини, доступність %), скільки разів перезапускався Мольфар і чому, скільки він був недоступний, відвал Wi-Fi, скільки роутер був недоступний і скільки разів перезавантажувався. Нижче — таймлайн, таблиця по днях (за рік — по місяцях), повний список і CSV.

Сповіщення в Telegram надходять після відновлення («інтернет відновлено, не було 12 хв»), бо під час обриву їх однаково не доставити. Кожен тип вмикається окремо.

## Визначення провайдера

- Зовнішній IP і провайдер беруться з публічних сервісів по черзі: `ipinfo.io` → `ip-api.com` → `ifconfig.co` → `ipwho.is` (якщо один недоступний — питаємо наступний). Запит — раз на `isp_check_min` хвилин (за замовч. 10; `0` — вимкнено), ~150 запитів на добу.
- Провайдер ідентифікується за **номером автономної системи (ASN)**, а не за назвою: різні бази пишуть «Kyivstar» і «Kyivstar PJSC», але ASN той самий — тож перехід на інше джерело не дає хибної «зміни».
- Можливу зміну провайдера підтверджує **повторна перевірка через 20 с** — короткий збій не створює алерт.
- Зміна лише IP (динамічна адреса) пишеться в історію й журнал, але в Telegram не надсилається.
- Ookla speedtest також повідомляє провайдера й зовнішній IP — вони зберігаються з кожним тестом (колонка «Провайдер» у серіях).
- Якщо активний WireGuard-тунель з `AllowedIPs = 0.0.0.0/0`, зовнішній IP буде IP VPN-сервера — інтерфейс про це попереджає.

## Як рахуються показники

- **Втрати** = (надіслано − отримано) / надіслано за одну перевірку.
- **Джитер (пінг)** = середня абсолютна різниця між сусідніми RTT (як у RFC 3550 і Ookla).
- **Speedtest-серія** — середнє лише успішних тестів; тести з помилкою зберігаються, але в середнє не входять.
- Під час speedtest пінг ставиться на паузу (налаштовується), щоб завантажений канал не давав хибних алертів про втрати.
- Історія агрегується: доба — кошики по 5 хв, тиждень — 1 год, місяць — 4 год, рік — 1 доба. Сирі дані зберігаються 400 днів (налаштовується).

## Поради

- Підключайте Pi **кабелем** до роутера — Wi-Fi Zero 3 сильно занижує speedtest.
- Ookla CLI на Zero 3 видає кілька сотень Мбіт/с; Python-рушій (`speedtest-cli`, запасний) упирається в CPU раніше — для каналів >300 Мбіт/с використовуйте Ookla.
- Сервер speedtest вибирається в **Налаштування → Speedtest → Вибрати…**: найближчі сервери, пошук за містом або провайдером, ID вручну. Кнопка «Тест» біля сервера запускає разовий тест на ньому, не змінюючи налаштувань.
- Карта пам'яті: запис невеликий (~1 рядок на адресу за перевірку), але для довгої роботи краще якісна карта (A1/A2) або збільшити інтервал пінгу.
- Якщо WireGuard показує «статус недоступний» — перевірте `sudo -u molfar sudo -n wg show all dump`.
