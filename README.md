# Мольфар — моніторинг мережі на Orange Pi Zero 3

*English version: [README.en.md](README.en.md)*

Легкий сервіс (Python + SQLite, ~40 МБ RAM), який:

- **Speedtest** — щодня у вибраний час запускає серію (за замовчуванням 5 тестів з інтервалом 5 хв) і зберігає середнє; кнопки «Один тест», «Серія», «Зупинити».
- **Вибір сервера speedtest** — автовибір найближчого або конкретний сервер зі списку / пошуку. Якщо вибраний сервер недоступний, тест можна автоматично повторити на автовибраному (у результаті буде позначка «[замість …]»).
- **Пінг** — постійно (за замовчуванням раз на 60 с по 20 пакетів) пінгує `1.1.1.1`, `8.8.8.8` і третю адресу на ваш вибір; рахує втрати, RTT (мін/сер/макс) і **джитер**.
- **Історія** — графіки й підсумки за добу / тиждень / місяць / рік, експорт у CSV.
- **Telegram** — сповіщення при високих втратах (N перевірок поспіль вище порогу), повідомлення про відновлення з тривалістю збою, опційно — підсумок кожної серії та алерт про низьку швидкість. Якщо інтернету немає, повідомлення чекають у черзі й надходять, щойно зв'язок повернеться.
- **Провайдер** — визначає поточного інтернет-провайдера (назва, номер AS, зовнішній IP, місто) раз на 10 хв і після кожного speedtest. Історія змін провайдера та IP, провайдер у таблиці серій, сповіщення в Telegram при зміні (зручно, якщо є резервний канал).
- **WireGuard** — вкладка для керування профілями: додати (вставити / завантажити `.conf` або через майстер з генерацією ключів), редагувати, увімкнути/вимкнути тунель, автозапуск, видалити. Стан (handshake, трафік) — і на «Огляді».
- **Дві мови** — українська та англійська (перемикач UK/EN у шапці або «Налаштування → Загальне»). Мова діє на веб-інтерфейс, Telegram-сповіщення та журнал.
- Веб-інтерфейс з паролем (змінюється прямо в налаштуваннях), адаптований під телефон, світла й темна теми.

## Встановлення

На Orange Pi (Armbian / Debian / Ubuntu):

```bash
# скопіюйте папку molfar на пристрій, напр.: scp -r molfar user@<ip>:~
cd ~/molfar
sudo ./install.sh
```

Скрипт сам готує систему:

1. **Годинник** — ставить часовий пояс `Europe/Kyiv`, вмикає NTP; якщо NTP не відповідає, бере час з HTTP-заголовка (у Zero 3 немає батарейки RTC, а з неправильним часом apt не працює).
2. **Обов'язкові пакети** — `python3`, `python3-venv`, `python3-pip`, `iputils-ping`, `iproute2`, `wireguard-tools`, `nftables` (потрібен wg-quick для профілів з `AllowedIPs = 0.0.0.0/0`), `sudo`, `curl`, `ca-certificates`, `unzip`, а також NTP-клієнт `systemd-timesyncd` (якщо немає chrony/ntp).
3. **Мережеві утиліти** — `dig`/`nslookup`, `traceroute`, `mtr`, `netstat`/`ifconfig`, `ethtool`, `iperf3`, `tcpdump`, `iftop`, `nload`, `sqlite3`, `fake-hwclock`. Ставляться «за можливості»: якщо якогось пакета немає, встановлення не зупиняється.
4. **WireGuard** — перевіряє модуль ядра; для `DNS =` у профілях налаштовує `resolvconf` (через `systemd-resolved`, якщо він працює, інакше ставить `openresolv`).
5. Ookla Speedtest CLI, користувач `molfar`, сервіс systemd, sudo-правила — і в кінці таблиця перевірки ✓/✗.

Змінні: `TIMEZONE=Europe/Warsaw` (або `keep`), `PORT=8081`, `EXTRA_TOOLS=0` (без утиліт), `MOLFAR_PASSWORD=…`, напр. `sudo TIMEZONE=keep EXTRA_TOOLS=0 ./install.sh`.

**Вхід у веб-інтерфейс за замовчуванням: `admin` / `Molfar`.** Поки діє пароль за замовчуванням, інтерфейс показує попередження. Змініть його в **Налаштування → Пароль веб-інтерфейсу** або задайте одразу при встановленні: `sudo MOLFAR_PASSWORD=МійПароль ./install.sh`. Повторний запуск `install.sh` оновлює код, дані зберігаються.

**Забули пароль?** `sudo molfar-reset-password` — повертає пароль з `/etc/molfar.env` (за замовчуванням `Molfar`).

| Що | Де |
|---|---|
| Код | `/opt/molfar` |
| База даних | `/var/lib/molfar/molfar.db` |
| Логін, пароль за замовчуванням, порт | `/etc/molfar.env` (після змін: `sudo systemctl restart molfar`) |
| Пароль, змінений у веб-інтерфейсі | у базі як хеш PBKDF2 (не відкритим текстом) |
| Логи | `journalctl -u molfar -f` |

## Віддалений доступ через WireGuard

Сервіс слухає `0.0.0.0:8080`, тож доступний з будь-якої мережі, яку маршрутизує ваш WireGuard (10.10.105.x, 10.10.106.x …).

- **WireGuard на роутері, Pi у його LAN** — нічого додатково не треба: підключіться до тунелю і відкрийте `http://<LAN-IP Pi>:8080`. Бажано закріпити за Pi статичний IP (DHCP-резервація на роутері).
- **Pi сам є WireGuard-піром** — див. `deploy/wg0.conf.example` (з `PersistentKeepalive = 25`, щоб Pi був доступний з-за NAT).

### Профілі WireGuard у веб-інтерфейсі

Вкладка **WireGuard** керує тунелями, через які Мольфар сам підключається до ваших мереж (`/etc/wireguard/<назва>.conf` + `wg-quick@<назва>`):

- **Додати** — вставте `.conf` від роутера, завантажте файл або заповніть **майстер** (кнопка «Згенерувати» створює ключі; публічний ключ передайте адміністратору сервера).
- **Редагувати** — приватний ключ показується як `<hidden>` і зберігається без змін, якщо його не замінити. Перед записом робиться копія `<назва>.conf.bak`. Активний тунель перезапускається.
- **Увімкнути / Вимкнути / Автозапуск / Видалити** — кнопки на картці профілю.
- **Захист від втрати доступу.** Після увімкнення або зміни активного тунелю браузер за кілька секунд підтверджує, що Мольфар досі доступний. Якщо підтвердження не надійде за 60 с (наприклад, `AllowedIPs = 0.0.0.0/0` «забрав» увесь трафік), тунель автоматично вимкнеться.
- **Безпека.** Веб-сервіс не має root: усі зміни виконує помічник `/usr/local/sbin/molfar-wg`, дозволений через sudo лише йому. Помічник сам перевіряє кожен параметр і **забороняє `PreUp/PostUp/PreDown/PostDown/SaveConfig`** — вони виконують довільні команди від root. Профілі з такими рядками, створені вручну, показуються «лише для перегляду»; редагуйте їх через SSH.

Перевірка на пристрої після оновлення:
```bash
sudo -u molfar sudo -n /usr/local/sbin/molfar-wg list    # {"ok": true, "profiles": [...]}
sudo wg show                                              # після «Увімкнути» у вебі
systemctl status wg-quick@<назва> --no-pager
```

Третьою адресою пінгу зручно ставити шлюз іншого сайту (напр. `10.10.106.1`) — тоді видно і якість самого тунелю.

## Telegram

1. У [@BotFather](https://t.me/BotFather) створіть бота (`/newbot`) → отримаєте токен.
2. Напишіть своєму боту будь-що, потім відкрийте `https://api.telegram.org/bot<ТОКЕН>/getUpdates` — `chat.id` у відповіді і є Chat ID (для групи — додайте бота в групу, id буде від'ємним).
3. Веб-інтерфейс → **Налаштування → Telegram** → вставте токен і Chat ID → «Надіслати тестове» → увімкніть сповіщення.

Логіка алерту: якщо втрати ≥ порогу (за замовч. 10%) **N перевірок поспіль** (за замовч. 3) — приходить 🔴; коли втрати падають нижче порогу — 🟢 з тривалістю проблеми. «Пауза між алертами» не дає спамити при нестабільному зв'язку.

## Визначення провайдера

- Зовнішній IP і провайдер беруться з публічних сервісів по черзі: `ipinfo.io` → `ip-api.com` → `ifconfig.co` → `ipwho.is` (якщо один недоступний — питаємо наступний). Запит — раз на `isp_check_min` хвилин (за замовч. 10; `0` — вимкнено), ~150 запитів на добу.
- Провайдер ідентифікується за **номером автономної системи (ASN)**, а не за назвою: різні бази пишуть «Kyivstar» і «Kyivstar PJSC», але ASN той самий — тож перехід на інше джерело не дає хибної «зміни».
- Можливу зміну провайдера підтверджує **повторна перевірка через 20 с** — короткий збій не створює алерт.
- Зміна лише IP (динамічна адреса) пишеться в історію й журнал, але в Telegram не надсилається.
- Ookla speedtest також повідомляє провайдера й зовнішній IP — вони зберігаються з кожним тестом (колонка «Провайдер» у серіях).
- Якщо активний WireGuard-тунель з `AllowedIPs = 0.0.0.0/0`, зовнішній IP буде IP VPN-сервера — інтерфейс про це попереджає.

## Як рахуються показники

- **Втрати** = (надіслано − отримано) / надіслано за одну перевірку.
- **Джитер (пінг)** = середня абсолютна різниця між сусідніми RTT (як у RFC 3550 і Ookla).
- **Speedtest-серія** — середнє лише успішних тестів; тести з помилкою зберігаються, але в середнє не входять.
- Під час speedtest пінг ставиться на паузу (налаштовується), щоб завантажений канал не давав хибних алертів про втрати.
- Історія агрегується: доба — кошики по 5 хв, тиждень — 1 год, місяць — 4 год, рік — 1 доба. Сирі дані зберігаються 400 днів (налаштовується).

## API

Усе, що робить веб-інтерфейс, доступно через HTTP (Basic Auth):

| Метод | Шлях | |
|---|---|---|
| GET | `/api/status` | поточний стан, останні результати, WireGuard, система |
| GET/POST | `/api/settings` | читання/збереження налаштувань (JSON) |
| POST | `/api/speedtest/start` | `{"mode":"single"}` або `{"mode":"series"}`; опційно `"server_id"` — разово на іншому сервері |
| POST | `/api/speedtest/stop` | зупинити тест/серію |
| GET | `/api/speedtest/servers` | найближчі сервери (`?refresh=true` — оновити), `?search=Київ` — пошук |
| POST | `/api/ping/run` | позачергова перевірка пінгу |
| GET | `/api/history/ping?range=day\|week\|month\|year` | агрегована історія пінгу |
| GET | `/api/history/speed?range=…` | тести й серії за період |
| GET | `/api/export/ping.csv?range=…`, `/api/export/speed.csv?range=…` | CSV |
| GET | `/api/events` | журнал подій |
| POST | `/api/telegram/test` | тестове повідомлення |
| GET | `/api/isp` | поточний провайдер + історія змін |
| POST | `/api/isp/check` | визначити провайдера зараз |
| GET | `/api/auth` | користувач і джерело пароля |
| POST | `/api/auth/password` | `{"current":"…","new":"…"}` — зміна пароля |
| GET/POST | `/api/wg/profiles` | список профілів / створити `{"name","config"}` |
| GET/POST/DELETE | `/api/wg/profiles/{name}` | конфіг (ключ прихований) / зберегти `{"config"}` / видалити |
| POST | `/api/wg/profiles/{name}/up\|down\|enable\|disable\|confirm` | керування тунелем |
| POST | `/api/wg/keygen`, `/api/wg/pubkey` | пара ключів / публічний ключ з приватного |

## Поради

- Підключайте Pi **кабелем** до роутера — Wi-Fi Zero 3 сильно занижує speedtest.
- Ookla CLI на Zero 3 видає кілька сотень Мбіт/с; Python-рушій (`speedtest-cli`, запасний) упирається в CPU раніше — для каналів >300 Мбіт/с використовуйте Ookla.
- Сервер speedtest вибирається в **Налаштування → Speedtest → Вибрати…**: найближчі сервери, пошук за містом або провайдером, ID вручну. Кнопка «Тест» біля сервера запускає разовий тест на ньому, не змінюючи налаштувань.
- Карта пам'яті: запис невеликий (~1 рядок на адресу за перевірку), але для довгої роботи краще якісна карта (A1/A2) або збільшити інтервал пінгу.
- Якщо WireGuard показує «статус недоступний» — перевірте `sudo -u molfar sudo -n wg show all dump`.

│   ├── app.py              HTTP API
